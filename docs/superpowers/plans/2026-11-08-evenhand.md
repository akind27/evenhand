**Goal:** A working web app where a rental shop and a renter replace the passport-as-deposit with a PayPal sandbox hold, AI compares pickup and return photos, and the hold is released or partly captured with both sides seeing the same sealed evidence.

**Architecture:** Next.js App Router app (pages + route handlers) on Vercel. All business rules live in pure TypeScript under `src/lib` (money, events, state, settlement); side effects go through three adapters with real and fake implementations (`PaymentsGateway`, `VisionAssessor`, `EvidenceStore`). Each handover is an append-only, hash-chained event log; current state is computed from it.

**Tech Stack:** Node 22, Next.js 16.4.5, React 19.3.1, TypeScript 5.9.3, Tailwind CSS 4.3.5, zod 4.6.7, @anthropic-ai/sdk 1.6.0 (model `claude-opus-5-5`), @paypal/react-paypal-js 10.6.1 + PayPal REST v2 (sandbox), @vercel/blob 2.8.2, ag-grid-react / ag-grid-community 36.3.0, qrcode 1.5.4, Vitest 5.1.0 (+ @vitest/coverage-v8 5.1.0, jsdom 31.0.0, @testing-library/react 16.3.3), Playwright 1.65.0.

## Global Constraints

- Money is always integer cents (`number`, integer, ≥ 0). Currency `EUR` only. Decimal strings exist only at the PayPal boundary (`"150.00"`).
- PayPal base URL is exactly `https://api-m.sandbox.paypal.com`. The app refuses to start if `PAYPAL_ENV` is anything other than `sandbox` (or unset in demo mode).
- Claude model ID is exactly `claude-opus-5-5`. Effort: photo check `low`, condition `medium`, comparison `high`. Server-side fallback `fallbacks: "default"` with beta `server-side-fallback-2026-07-01`.
- AI confidence bar `CONFIDENCE_BAR = 0.75`: findings below it get status `needsHuman`; at or above it `proposed`. Only `confirmed` findings are ever charged. The AI never moves money.
- Photo angles: `front`, `back`, `left`, `right` are required at pickup and return; up to 4 `closeup`. Photos are JPEG, resized in the browser to a 1600 px long edge, quality 0.85; the server rejects anything that is not JPEG (magic bytes `FF D8 FF`) or is larger than 3 MB.
- PayPal authorization: honor period 3 days, valid 29 days.
- Retention: real handovers deleted 30 days after closing, demo data after 7 days (documented; the cleanup job is out of scope).
- Every AI result shown on screen carries the label **"AI-assisted — a person decides any charge."** Renter-facing AI explanations carry **"AI-written explanation"**.
- No identity documents or faces: the photo check returns `personVisible`; if true the photo is unusable with reason "Please photograph only the vehicle."
- UI text English first; renter screens also `el`, `de`, `it`, `fr`.
- Keyless demo mode: when `PAYPAL_CLIENT_ID`/`PAYPAL_CLIENT_SECRET` are missing the app uses the fake gateway; when `ANTHROPIC_API_KEY` is missing it uses recorded answers. Both are shown on screen with a visible "Demo mode" badge.
- Licence MIT. Test output folders (`test-results/`, `playwright-report/`, `coverage/`) stay git-ignored and vercel-ignored (already configured).

## Review Focus

1. **Double taps and races** (Release, Accept, Authorize pressed twice, or two tabs): exactly one PayPal void/capture happens; the second call returns the current state without error. → tests in Task 7 (`idempotent release`, `idempotent accept`) and Task 5 (`PayPal-Request-Id` header per action).
2. **Hold no longer valid** (authorization expired after 29 days, or voided/captured outside the app): the app shows a clear status ("Hold expired — settle with the renter directly") and does not crash or charge. → Task 5 error mapping tests, Task 7 `expired hold` test.
3. **Damage above the deposit**: capture is capped at the held amount; the screen shows the excess as "exceeds the deposit — settle separately". → Task 2 `computeCharge caps at hold` test.
4. **AI failure** (refusal, invalid JSON, timeout, API error, or keyless demo with unknown photos): the flow continues; the result is "needs a human look"; the shop can mark "no damage" or add a finding by hand. → Task 6 failure tests, Task 7 `compare failure falls back to manual` test.
5. **Wrong person acting** (renter link opened elsewhere, missing/invalid token, renter calling shop actions, shop calling renter actions): 403 with no state change; the read-only record link can never act. → Task 8 auth tests, Task 9 route tests.

- Transition rules for `canApply` (copy exactly):
  - `photoAdded` pickup: status `draft`; return: status `returning`. At most 4 `closeup` per phase.
  - `photoChecked`: the photo exists. `conditionRecorded`, `depositSet`: status `draft`. `depositSet.ruleId` must exist in `depositRules` and `amountCents` must equal that rule's amount.
  - `sharedWithRenter`: status `draft`, no missing pickup angles, every required-angle photo checked usable or overridden, `conditionRecorded` happened, deposit set → status `awaitingRenter`.
  - `renterConfirmed`: status `awaitingRenter` and not yet confirmed. `holdAuthorized`: status `awaitingRenter`, renter confirmed, `amountCents === deposit.amountCents` → `active`.
  - `holdReauthorized`: status in `active | returning | reviewed | disputed`.
  - `returnStarted`: `active` → `returning`. `comparisonDone`: `returning` with no missing return angles → `reviewed`.
  - `findingAdded`, `findingUpdated`: status `reviewed`; `findingUpdated` needs an existing finding; `priceItemId` must be null or in `priceList`.
  - `released`: status `reviewed`, no `confirmed` finding, hold present → `released`.
  - `charged`: status `reviewed`, at least one `confirmed` finding with a price → `charged`.
  - `disputed`: status `reviewed` → `disputed`. `holdLost`: hold present and not settled (status stays; `holdLost` set).
  - `closed`: status in `released | charged | disputed`.

  - Void: `POST /v2/payments/authorizations/{id}/void`, request id `<handoverId>:void` (204 = success).
  - Capture: `POST /v2/payments/authorizations/{id}/capture` body `{ amount: { currency_code: 'EUR', value }, final_capture: true, note_to_payer: note }`, request id `<handoverId>:capture`.

  - Status: `GET /v2/payments/authorizations/{id}` → `status`.

Never log the token or secret.
